# NYC Incident Intelligence Agent

A web-based AI agent that helps NYC municipal transportation staff retrieve and understand historical motor vehicle collision data. A user selects a borough, asks a question in natural language, and receives a source-grounded briefing generated by Anthropic Claude using NYC Open Data (records available up to June 2026).

See [PLAN.md](PLAN.md) for the day-by-day build plan, shared API contract, and eval cases.

## 🛠 Setup & Installation

This project uses a Python backend (FastAPI), a React frontend (Vite), and an `.env` file to manage credentials securely.

**1. Clone the repository**
```bash
git clone <repository-url>
cd nyc-incident-agent
```

**2. Set up the backend virtual environment**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
```

**3. Configure environment variables**
```bash
cp .env.example .env
```
Do not commit the `.env` file. Populate it with your own values (see the table below).

**4. Run the backend**
```bash
cd backend
uvicorn main:app --reload --port 8000
```

**5. Run the frontend** (in a second terminal)
```bash
cd frontend
npm install
npm run dev
```
Open the local URL Vite prints (typically `http://localhost:5173`).

> Run commands are a starting point. Update them if the final project layout differs.

## 🔑 Configure Environment Variables

| Variable | Required | Description |
|---|---|---|
| `ANTHROPIC_API_KEY` | Yes | Anthropic API key. Server-side only. Never place it in frontend code, screenshots, or commits. |
| `NYC_OPEN_DATA_APP_TOKEN` | No | Socrata App Token to bypass anonymous rate limits. Leave blank to run without a token. |
| `USE_FIXTURES` | No (default `true`) | `true` serves labeled fixture data. Set `false` to query the live NYC Open Data endpoint. |
| `ANTHROPIC_MODEL` | No | Claude model ID used by the agent. |
| `REQUEST_TIMEOUT_SECONDS` | No (default `10`) | Timeout for NYC Open Data and Anthropic calls. |
| `ALLOWED_ORIGINS` | No | Frontend URLs allowed by CORS, e.g. `http://localhost:5173`. |

Frontend (`frontend/.env`): `VITE_API_BASE_URL` (not a secret). Never put a key in a `VITE_` variable; it ships to the browser.

## 🔌 API

`POST /api/briefing`

```json
{ "borough": "Queens", "question": "What traffic incidents were reported in Queens?" }
```

| Status | Meaning |
|---|---|
| `success` | Records retrieved, briefing generated and validated |
| `no_results` | Source responded with zero matching records |
| `data_unavailable` | The collision data source failed |
| `model_unavailable` | The Anthropic API failed |

## 🛡️ Safeguards & Blast Radius

Because this agent operates in a municipal transportation context, strict safeguards are in place:

- **Read-Only:** The retrieval tool (`query_nyc_open_data`) is read-only. It cannot modify official records, dispatch responders, or issue public warnings.
- **No Data Fabrication:** The system prompt prohibits inventing crash locations, statuses, timestamps, or severity. Briefings are checked by `validate_agent_response` before display.
- **Honest Failure States:** If retrieval succeeds with zero matches, the app returns `no_results`. If the data source fails, `data_unavailable`. If Claude fails, `model_unavailable`. A failure is never shown as an empty success.
- **Untrusted Source Data:** Incident descriptions and API responses are treated as untrusted. Instructions embedded in them are ignored.
- **Secrets Server-Side:** The Anthropic API key stays in server-side environment variables and is never exposed to the browser or committed to GitHub.
- **Graceful Degradation:** Python error handling returns clean failure messages on API timeouts instead of stack traces.
- **Human Review:** Output supports human situational awareness only. Operators verify sources and timestamps before acting.

## 🚫 Out of Scope for MVP

- **Live Traffic & Active Disruptions:** Because the dataset is capped at June 2026, real-time monitoring of roadwork, live traffic jams, or active daily street closures is explicitly out of scope. The agent analyzes historical hazard patterns, not current conditions.
- **Push Notifications & Scheduled Alerts:** Slack integrations, email digests, scheduled cron-job monitoring (like a 7:00 AM automated run), and personalized alerts are designated as future enhancements. The agent strictly generates briefings on manual user request.
- **Operational Dispatch & Write Access:** The agent is strictly read-only for human situational awareness. It cannot dispatch emergency responders, file 311 service requests, modify Socrata databases, or execute municipal safety decisions.
- **Multi-Borough Aggregation:** The MVP focuses on a single complete user journey for one selected borough per query. City-wide comparative analytics or multi-borough cross-referencing are excluded from the initial release.

## 📊 Data Status

**Historical Data Only:** The agent relies on the NYC Open Data Motor Vehicle Collisions dataset, which currently contains historical records up to June 2026. It does not provide real-time or daily active disruption data. All briefings reflect historical hazard patterns rather than active daily conditions.
